## Parent

#30（spec: 对局诊断区块——闲置 stats 字段的结果归因）

## What to build

车队成员打开败局详情页时，诊断区块自动高亮这局的短板维度（如"视野得分全队倒数"）；每个诊断维度展示原始值、队内位次、与同英雄基线（scoring_baseline）的偏差。胜局也展示诊断（不高亮短板）。维度范围必须超出战报图既有三指标（输出占比/承伤占比/伤害转化），候选包括视野得分、控制时长、经济分配、资源控制等。

本票第一步：盘点 stats_json 全量字段清单，确定最终维度清单与短板判定规则（spec 的两个待细化项在此票内解决，产出记录在 issue 评论供后续参考）。诊断计算不混入 OP Score 评分体系（版本冻结在 v4）。

## Acceptance criteria

- [ ] stats_json 全量字段盘点结论与最终维度清单、短板判定规则记录在 issue 评论
- [ ] 诊断计算服务经既有 ParticipantStatsReader 门面读取 stats_json，不新开解析路径
- [ ] 每维度输出：原始值 + 队内位次 + 同英雄基线偏差 + 短板标记
- [ ] 败局自动高亮短板维度；胜局展示正常维度表现
- [ ] 诊断考虑英雄职业（辅助的视野/控制权重高，不因伤害低被误判全面垫底）
- [ ] 维度列表可扩展：新增维度不改已有字段结构
- [ ] 与 OP Score 评分体系完全隔离；纯数据不依赖 AI，秒出
- [ ] Web 详情页诊断区块与复盘区块各自独立（不合并同一 tab）
- [ ] TDD：维度计算/位次/短板判定/职业差异化的 service 层单测先行，先例为评分引擎维度计算测试
- [ ] 纯 Web 展示，不进 QQ 推送
