# Spec: 车队组合学——搭档胜率矩阵与时段胜率

> 五项数据价值深挖计划第 ④ 项（增量迭代）。术语见后端 `CONTEXT.md`（搭档胜率矩阵）。

## Problem Statement

车队成员常问"我跟谁搭档胜率最高""咱们车队几点开黑最容易赢"，但现在没有任何
组合维度的统计：榜单都是个人维度（MVP/OP Score/战犯等），对局数据里明明有每局的
全员参赛者信息可以回答这些问题。

## Solution

榜单中心新增"组合"tab：搭档胜率矩阵（N×N，N 为车队成员数）、时段胜率、常用
阵容胜率。只统计车队对局；小样本格子以局数标注而非裸百分比，避免"2 局 100%
胜率"式误导。矩阵类数据适合交互式探索，不进周报叙事。

## User Stories

1. 作为车队成员，我在榜单中心打开"组合"tab，看到全部成员两两搭档的胜率矩阵。
2. 作为车队成员，矩阵每格同时展示胜率与局数，我能自行判断样本量是否可信。
3. 作为车队成员，样本量低于阈值的格子有明确的"样本不足"视觉处理（弱化/置灰），不被裸百分比误导。
4. 作为车队成员，我点击矩阵某格，能看到这对搭档的全部车队对局列表（可追溯胜率来源）。
5. 作为车队成员，我按时段（分桶维度待细化）查看车队胜率，知道车队几点开黑状态最好。
6. 作为车队成员，我查看常用阵容（定义待细化）的胜率，知道车队最稳的开黑配置。
7. 作为车队成员，组合统计只包含车队对局，不含单人路人局（与周报/榜单口径一致）。
8. 作为维护者，跨数据源（LCU/SGP/Riot 回填）的成员匹配走成员身份集合，两套 puuid 不混淆。
9. 作为开发者，组合统计复用 FleetGameLoader 的车队对局装载与判定口径，不重写第二套。

## Implementation Decisions

- **组合统计服务**：在 FleetGameLoader 之上新增组合统计服务（车队对局判定/装载
  全部复用），成员匹配经 TeamRosterService 身份集合。
- **搭档胜率矩阵**：N×N 对称矩阵，每格胜率 + 局数；对角线（成员个人车队局数据）
  展示方式待定。**小样本阈值待细化**。
- **时段胜率**：时段分桶方式（小时段/晚高峰等）**待细化**。
- **常用阵容**：定义（全 5 人阵容 / 核心组合）**待细化**。
- **点击下钻**：矩阵格子下钻到对局列表为增强项，一期可为二期。
- **前端**：榜单中心新增"组合"tab，复用七榜的基建（查询参数框架、日期区间等）。
- **路由层约定**：controller 参数校验 + 返回封装，聚合逻辑在 service 层。

## Testing Decisions

- 好的测试只测外部行为：给定车队对局集合断言矩阵/时段统计结果，不测内部遍历方式。
- **service 层测试**：先例为 LeaderboardService / MemberStatsService 的车队聚合测试。
- **身份集合测试**：跨两套 puuid 的对局正确归到同一成员（先例：TeamRosterService
  身份集合测试、ADR 0002）。
- **小样本标注测试**：低样本格子的返回结构带局数，前端可判定。
- **口径一致性测试**：组合统计的对局集合与七榜/周报的车队对局集合同口径。
- 测试路径与被测文件保持一致，遵循 TDD 红绿灯。

## Out of Scope

- 周报固定的组合区块（"本周最佳搭档"叙事）。
- 英雄组合学（英雄搭配胜率，而非成员搭档）——可作后续独立 idea。
- 跨车队/对局内对手组合分析。
- 阵容推荐类 AI 功能。

## Further Notes

- 三个"待细化"项（小样本阈值/时段分桶/常用阵容定义）是本 spec 实现前需要一轮
  简短确认的点，不阻塞其余部分先行。
- 车队 5 人规模下矩阵 5×5（或含替补略大），性能无压力，不需要预聚合表。
