# Spec: 时间线复盘系统——规则转折点 + AI 叙述 + 回填补拉时间线

> 五项数据价值深挖计划第 ② 项（核心投入，在周报流式化之后实现）。
> 术语见后端 `CONTEXT.md`（时间线复盘 / 关键转折点），决策依据：
> `docs/adr/0008-timeline-replay-rules-plus-ai.md`。

## Problem Statement

车队成员打完一局（尤其败局）后，只能看到结果性数据（KDA、伤害、评分），看不到
**过程**：经济差是怎么拉开又怎么被翻盘的、哪一波团灭是崩盘起点。库内
`match_timeline.frames_json`（逐分钟经济/经验/补刀/伤害/位置 + 事件流）是完全
未利用的最大数据资产。且历史回填的对局（每人最多 200 局）全部缺失时间线——
回填管道只拉对局列表与详情，不拉 timeline。

## Solution

Web 对局详情页新增"复盘"区块：经济差曲线 + 击杀事件标记 + 关键转折点高亮。
转折点由后端规则引擎从 frames **确定性提取**（可测、可复算），AI 叙述按需手动
触发、SSE 流式输出，只解读不编造。backfill 流程补拉 MATCH-V5 timeline，使复盘
覆盖全部历史对局。无时间线的对局优雅降级。

## User Stories

1. 作为车队成员，在对局详情页打开复盘区块，看到整局的经济差曲线（正=我方领先）。
2. 作为车队成员，经济差曲线上的击杀事件有可悬停/点击的标记，能看到击杀时刻与涉及成员。
3. 作为车队成员，关键转折点（一血、团灭、大龙、经济差极值、经济反超时刻）在曲线上高亮标注，一眼看出这局的胜负手。
4. 作为车队成员，我点击"AI 复盘"按钮后，AI 基于真实转折点流式输出有观点的败局/胜局叙述（打字机效果）。
5. 作为车队成员，AI 复盘叙述中的每个关键节点都能对应到曲线上的真实转折点，不会出现"AI 编造的团战"。
6. 作为车队成员，查看一个没有时间线数据的对局时，复盘区块显示降级提示与 stats 层面的简要信息，而不是空白曲线或报错。
7. 作为车队成员，历史回填的对局也能完整复盘（时间线已被补拉齐）。
8. 作为维护者，运行 backfill 时，已入库但缺时间线的对局被自动补拉 Riot MATCH-V5 timeline，受既有滚动窗口限流保护。
9. 作为维护者，补拉的 Riot timeline 帧与桌面端 LCU/SGP 帧格式差异经过转换适配，两源数据对下游消费端格式统一。
10. 作为维护者，转折点规则引擎的判定结果可以从 frames 复算验证，出问题能定位是规则还是数据。
11. 作为开发者，AI 叙述端点复用单局 AI 分析的 SSE 事件契约（含重试与 reasoning 处理），不新造契约。
12. 作为前端用户，复盘曲线复用前端已有的差距曲线组件能力（对局卡片内已有按 totalGold/xp/cs/damage 维度画差曲线的组件），升级为完整复盘视图。

## Implementation Decisions

- **转折点规则引擎**：纯函数服务（frames 输入 → 转折点列表输出），候选类型至少包括
  经济差极值、一血、团灭（时间窗内多杀）、大龙、经济反超时刻；每个转折点携带真实
  上下文（游戏内时刻、双方经济差、涉及成员与事件明细）。规则参数可配置。
- **AI 叙述**：手动按钮触发，SSE 流式，事件契约复用单局 AI 分析既有约定；
  AI 的输入是**转折点列表 + 一局摘要**（车队视角），不喂原始 frames。
- **回填补拉时间线**：backfill 流程新增"对局已入库但缺时间线 → 补拉
  MATCH-V5 `/match/v5/matches/{matchId}/timeline`"步骤，写入走既有时间线入库管道
  （幂等键 game_id）；实现前必须先做 Riot 帧格式与 LCU/SGP 帧格式的比对，
  不兼容处做转换适配，保证下游消费端格式统一。
- **优雅降级**：无时间线对局（补拉失败、回填上限外）复盘区块降级为 stats 层面
  简要信息，不渲染曲线。
- **一期不含位置玩法**：frames 中的逐分钟位置坐标（死亡热力图、游走轨迹、开局
  路线）明确不做，留作二期独立 idea。
- **路由层约定**：controller 只做参数校验与 SSE 装配；转折点提取、AI 编排、
  补拉逻辑全部下沉 service 层。
- **前端**：详情页新增复盘区块（tab 或区块），曲线复用 Chart.js 与既有差距曲线
  组件先例，事件标记与转折点高亮为新增交互。

## Testing Decisions

- 好的测试只测外部行为：给定 frames 断言转折点列表（黄金样本可复算）、SSE 事件
  序列、降级行为；不测引擎内部私有方法。
- **转折点引擎单测**：先例为 OP Score 评分引擎 / MatchMvpService 的纯计算单测，
  构造含已知事件的 frames 样本，断言提取结果。
- **AI 叙述 SSE 契约测试**：先例为单局 AI 分析 SSE 集成测试。
- **回填补拉测试**：mock Riot HTTP 响应（先例为 Riot 客户端与限流测试），断言
  已入库缺时间线的对局被补拉、已有时间线的不重复拉、限流窗口生效。
- **帧格式转换测试**：Riot timeline 黄金样本 → 转换结果与 LCU/SGP 帧结构一致的
  断言。
- **降级测试**：无时间线对局的详情响应不含曲线数据、复盘区块可判定降级。
- 测试路径与被测文件保持一致，遵循 TDD 红绿灯。

## Out of Scope

- 位置玩法（死亡热力图、游走轨迹、开局路线分析）——二期。
- QQ 推送复盘图（交互式曲线不适合静态图）。
- 对局入库时自动生成 AI 复盘（手动触发，没兴趣的局不花钱）。
- AI 从原始 frames 自行"发现"转折点（无法复算、可能编造，已明确否决）。

## Further Notes

- `match_timeline` 的写入路径从 1 条（桌面端实时推送）变为 2 条（+回填补拉），
  幂等键不变，但两源帧格式差异是本 spec 最大的实现风险点（ADR 0008 Consequences）。
- 回填耗时与 Riot API 限流压力增加（每局多一次 timeline 调用），需纳入既有
  滚动窗口限流预算。
