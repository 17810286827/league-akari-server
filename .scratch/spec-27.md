## Problem Statement

路由层承载了业务编排：对局同步接口在 controller 里直接调用局后播报协调器，违反项目自己定下的分层规则（"controller 只做参数校验和返回值封装"），也让路由层多了一个与"接收请求、返回响应"无关的依赖。

公共 DTO 包无限膨胀且无主：14 个 DTO 平铺在一个包里，周报响应只有车队域用、对局同步请求只有对局域用，归属要靠猜，新人或 agent 每次都要全局搜索确认。

车队聚合服务是个准上帝类：约千行代码、13 个构造依赖，周报/榜单/成员列表/成员卡四种查询口径全在一个类里，还直接注入了对局域、评分域的多个服务——任何一种口径的改动都在同一个巨型类里进行，review 与回归验证范围被无谓放大。

## Solution

三项纯结构收敛（零行为变化、对前端零影响）：

1. **播报编排事件化**：对局落库事务提交后发布"对局已同步"事件，播报协调器以"提交后执行"方式监听并做原有判定——controller 与播报彻底解耦，时序语义与现状逐字一致；
2. **dto 按域子包归位**：公共 dto 包拆出对局/车队/评分/账号/公共五个子包，纯机械搬家；
3. **车队聚合服务按查询场景拆分**：抽出共享的"车队对局装载器"与"七榜单计算引擎"，周报/榜单/成员拆为独立入口服务。

依赖既定的决策：事件化优于"折回摄取管道"（后者会让 QQ 外部调用发生在数据库事务内）与"维持现状"；dto 子包优于"DTO 进特性包"（后者与平铺 entity/mapper 骨架冲突且改动面过大）。

## User Stories

1. As a 后端维护者, I want controller 只做参数校验与返回值封装, so that 路由层不再承载业务编排，符合项目自己声明的分层规则
2. As a 后端维护者, I want 播报触发改为落库事务提交后的事件监听, so that 播报永远基于已提交数据判定，且发送期间的数据库连接不被外部 I/O 拖长
3. As a 车队播报功能, I want "每次同步都触发判定、状态机内部去重"的补推重试语义逐字保留, so that 桌面端轮询补推的兜底能力不受重构影响
4. As a 后端维护者, I want 播报协调器改为监听事件而 controller 不再依赖它, so that 两个模块间只靠事件契约关联
5. As a 前端开发者, I want 本次三项收敛不改变任何线上契约（路径、请求、响应、错误）, so that 前端零适配
6. As a 后端维护者, I want dto 按业务域分子包, so that 每个 DTO 的归属一眼可见，公共包不再无限膨胀
7. As a 后端维护者, I want 车队对局的装载与"车队局"判定抽成共享组件, so that 周报/榜单/成员卡的统计口径继续只有唯一来源
8. As a 后端维护者, I want 七榜单计算独立成引擎、周报与榜单入口共用, so that 新增榜单维度只改一处
9. As a 后端维护者, I want 周报/榜单/成员拆为独立入口服务, so that 单一口径的改动不再牵动巨型类的其他部分
10. As a 测试维护者, I want 现有集成测试全程绿灯作为重构安全网, so that "纯重构无行为变化"可以被验证而不是被声称
11. As a 排查问题的人, I want 拆分后保留装载/评分的分段计时日志, so that 榜单慢请求的定位能力不退化
12. As a 维护者, I want AGENTS.md 的包结构描述随本次收敛同步更新, so that 文档不再与代码漂移
13. As a 新接手者, I want controller 的依赖列表变短、各服务职责单一, so that 路由层与车队域的阅读成本下降

## Implementation Decisions

- **事件化编排**：对局摄取服务在落库事务内发布"对局已同步"事件（载荷为 gameId）；播报协调器从"被 controller 直调"改为"事务提交后（AFTER_COMMIT）监听"。关键语义对齐：
  - **每次同步都发布事件**（含幂等跳过的重复推送），是否播报仍由推送状态机内部判定——与现状（controller 无条件调用、协调器门控）逐字一致，补推重试路径不受影响；
  - 发送发生在事务提交后，与现状时序一致；监听阶段异常不会回滚已提交事务，"播报失败不影响同步响应"的既有语义保留；
  - 事件记录定义在发布方（对局域），监听在播报包——依赖方向与现状一致；项目已有启动恢复事件监听的基础设施，风格统一。
- **dto 按域子包**：对局域（同步请求、对局/时间线视图、称号视图）、车队域（周报/榜单/成员/成员卡视图）、评分域（评分视图）、账号域（Riot 账号视图）、公共（分页信封）。纯机械搬家 + import 修正，**不改任何字段与序列化行为**。
- **车队聚合服务拆分**：拆为"车队对局装载器"（对局装载 + 车队局判定 + 成员身份索引，含现有分段计时日志）、"七榜单计算引擎"（mvp/opscore/criminal/feeder/carry/signature/attendance，周报与榜单入口共用）、三个入口服务（周报聚合 / 榜单查询 / 成员与成员卡）；车队控制器改注入三个入口服务。自然周口径（Asia/Shanghai、周一 00:00 起算）与周区间工具随装载器归置，全部口径数值不变。
- **顺序约束**：本 spec 与 #26（统一响应契约与异常体系）都改动控制器与车队域文件，建议先执行 #26 再执行本 spec，减少同文件冲突；两份都落地后对分层契约文档做一次性重写。
- **提交风格**：Conventional Commits 中文描述，按"事件化 / dto 归位 / 聚合拆分"三个单主题提交拆分。

## Testing Decisions

- **核心原则**：本 spec 是纯重构——测试只断言外部可见行为（HTTP 契约、统计口径数值、播报状态机终态），断言本身除事件化适配外不做任何修改；"现有测试全绿"即验收标准。
- **测试接缝（全部为现有接缝，不新增）**：
  1. **HTTP 边界集成测试（最高接缝，事件化的主守卫）**：现有"对局同步→局后播报"端到端集成测试必须不改断言通过，证明事件化后触发链路语义不变；对局与车队控制器的既有集成测试同任守卫 dto 归位。
  2. **车队聚合行为守卫**：现有车队聚合单测随拆分镜像重组到新服务路径，断言数值不变——它是"口径唯一来源未被破坏"的证明。
  3. **播报协调器单测**：触发入口从方法直调改为事件监听，单测相应调整触发方式，状态机断言不变。
- **TDD 适用性说明**：本 spec 以"守卫测试先行跑绿、重构、再跑绿"的固定重构节奏执行，不新增红测试（无新行为）；唯一的新断言点是"controller 不再依赖播报协调器"可用架构层断言或依赖检查覆盖。

## Out of Scope

- #26 已覆盖的统一响应契约与异常体系改造（先行执行）。
- entity/mapper 归位、controller 包结构变动、更彻底的特性包迁移（dto 仅做子包化）。
- 任何统计口径、评分权重、播报判定条件的调整——本 spec 只动结构不动行为。
- 前端/桌面端的任何改动（无契约变化，无需适配）。
- 播报状态机内部实现与评分引擎内部实现。

## Further Notes

- 事件化后的完整链路：桌面端推送 → 同步接口（校验+落库）→ 事务提交 → 对局已同步事件 → 播报协调器判定（状态/开关/时间窗/车队局门控）→ 战报图+锐评。链路各环节的口径契约见 CONTEXT.md 与局后播报 spec。
- dto 子包化后 `PageResponse` 留在公共子包，它是跨域的分页信封；Riot 账号视图归账号域子包（车队域与账号域都会引用它，属跨域契约而非公共设施）。
- AGENTS.md 的重写刻意放在 #26 与本 spec 都落地之后一次性做，避免同一文件被两个改造各改一半。
