# MVP/SVP 采用职业差异化评分体系

对局同步时按英雄职业（射手/法师/坦克/刺客/战士/辅助）动态调整评分维度权重，对每队 5 名选手做同队归一化，胜方得分最高者为 MVP、负方得分最高者为 SVP，结果存入独立 `match_mvp` 表。

## Status

accepted

## Considered Options

- **英雄定位来源**：对局 `position`（分路）→ 否决，用户明确要按英雄固有职业分类，两者语义不同；改用数据库 `champion_class` 表 + Flyway 初始化（Riot Data Dragon 的 `tags` 提供基础数据）
- **计算时机**：查询时实时计算 → 否决（每次请求重复遍历 10 人数据）；改为同步写入时计算落库，查询零延迟
- **存储方案**：在 `match_participant` 上加点位 / 在 `match` 上加外键 → 否决（污染现有表结构）；改为独立 `match_mvp` 表，可存评分明细便于调试
- **归一化基准**：全场归一化 → 否决（输方整体被压制）；改为同队 5 人内 0-100 线性归一化，比队友打得好即高分
- **评分细则**：统一公式 → 否决（坦克的输出永远比不过 ADC，评选缺乏说服力）；刺客与战士共用"全能均衡"权重，大乱斗模式下辅助视野权重下调

## Consequences

- `champion_class` 表需维护英雄职业映射，新英雄/版本调整需迁移跟进，但不阻塞评分主流程（缺失职业可回退到均衡权重）
- 评分权重是算法常量，后续调参只需改权重配置，`score_detail_json` 保留原始值 + 归一化得分，便于追溯与可视化展示
- 只有"胜方第一 / 负方第一"两行数据落库；若用户信息查询接口需要展示"谁拿了 MVP"，需依赖 match_mvp 表与外键回查 participant
