# 0008. 时间线复盘：规则算点 + AI 叙述，回填补拉时间线

- 状态：已采纳（accepted）
- 日期：2026-09-05
- 关联：[0001-mvp-svp-role-adaptive-scoring](./0001-mvp-svp-role-adaptive-scoring.md)（"评分引擎可测、AI 只做锐评"哲学的延续）、
  [0007-weekly-ai-stream-and-persistence](./0007-weekly-ai-stream-and-persistence.md)（SSE 事件契约复用）

## 背景与问题

`match_timeline.frames_json` 是库内最大且完全未利用的数据资产（逐分钟经济/经验/补刀/
伤害/位置坐标 + 事件流），目前仅原样存取。决定基于它构建时间线复盘系统：
Web 对局详情页新增复盘区块（经济差曲线 + 事件标记 + 转折点高亮），AI 叙述手动触发、
SSE 流式输出。另发现回填管道（RiotMatchHistoryService）只拉对局列表与详情，
**不拉时间线**——历史回填的 200 局/人全部缺失时间线数据。

## 决策

1. **规则算点 + AI 叙述**：关键转折点（经济差极值、一血、团灭、大龙等）由后端
   确定性规则引擎从 frames 提取，每个转折点携带真实上下文数据；AI 只负责把这些点
   串成有观点的叙述，不负责发现事件。延续 ADR 0001 "评分可测、AI 不编造"的哲学：
   转折点可单测、可复算，AI 幻觉无从发生。
2. **回填补拉时间线**：backfill 流程新增"对局已入库但缺时间线 → 补拉
   MATCH-V5 `/match/v5/matches/{matchId}/timeline`"步骤，使复盘系统覆盖全部
   历史对局，而非仅桌面端采集后的对局。
3. **一期不含位置玩法**：frames 中的逐分钟位置坐标（死亡热力图、游走轨迹、
   开局路线）留作二期独立 idea，一期只做"经济差曲线 + 转折点 + AI 叙述"闭环。

## Considered Options

- **整段时间线交给 AI 自己找转折点** → 否决——AI 可能叙述出不存在的事件，
  token 消耗大，且转折点无法被测试复算
- **接受时间线只覆盖桌面端采集的局** → 否决——复盘功能上线初期将只能覆盖
  近期对局，历史 200 局/人的数据价值被浪费；补拉是一次性成本
- **一期就做位置轨迹/热力图** → 否决——数据现成但工作量翻倍，先把闭环跑通

## Consequences

- `match_timeline` 的写入路径从 1 条变 2 条（桌面端实时推送 + 回填补拉），
  幂等键 `game_id` 不变，但需注意 Riot timeline 与 LCU/SGP timeline 的帧格式
  差异（回填补拉时要确认 Riot frames 与现有消费端格式兼容）
- 没有时间线的对局（旧局且补拉失败、回填上限外的局）复盘区块需优雅降级：
  只展示 stats 层面的分析，不渲染曲线
- 回填耗时与 Riot API 限流压力增加（每局多一次 timeline 调用）
