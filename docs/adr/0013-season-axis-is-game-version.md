# 赛季以游戏版本为断代轴

新增「赛季资料」页需要"按赛季聚合"，但项目内不存在任何赛季目录（无赛季表、无赛季 API），Riot 也不提供赛季边界接口——台服/国服、极地大乱斗/海克斯乱斗各自的赛段边界无法自动判定。我们决定：一切"按赛季"的聚合一律以 `match.game_version` 经 `GameVersionNormalizer` 归一后的主次版本（如 `16.15`）为断代轴，页面上直接显示版本号，"赛季"与"版本"在本项目内是同一个东西。这样无需新增任何基础设施，且现有 `SeasonReportService` 已在内存里按归一版本分桶，口径天然一致。

## Considered Options

- **官方排位赛季（S15 等）**：需人工硬编码赛段起止日期，台服与国服不同、模式之间也不同，抄错无人能发现。CONTEXT 里"台服赛季边界判定需人工确认更稳"已是同一教训。
- **新建自定义赛季表（赛季名 + 起止日期，人工维护）**：数据源不存在，等于把 Riot 的排期表手工搬进配置，且引入持续的维护负担。
- **复用 `/season-report` 的人工填起止日期**：一次只能看一个区间、区间无法命名，做不出"每个赛季"的横向对比。

## Consequences

- 榜单中心"本赛季"（实现为当年 1 月 1 日至今）与 `/season-report` 的人工起止日期**都是本决策之前的遗留近似**，不随之改写；新页面不得复用它们作为赛季语义。
- 页面上不会出现赛季名（如"2026 夏季赛"），只有版本号；如果将来要显示赛季名，需要在版本号之上再叠一层人工映射，而不是替换这个轴。
- 没有对局的版本不会出现在统计里，空档必须如实显示为"无对局"，不得隐藏（隐藏会让读者把空白当成数据缺失）。
- 版本筛选器的选项必须动态取自库里有数据的版本：`LeaderboardsView.vue` 里硬编码的 `VERSION_OPTIONS`（16.10~16.16）是既有缺陷，不得作为新页面的版本全集。
