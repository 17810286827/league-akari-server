# 英雄×强化统计的样本取全库全量参与者行

新增「赛季资料 /season-archive」的英雄×海克斯强化统计需要圈定取行范围。库里每局海克斯乱斗存有全部 10 名参与者的 `stats_json`（含强化），车队成员身份集合与车队对局两套既有口径（七榜/周报/成员卡）都只取"自己人"的行。我们决定：**全库全量参与者行**（含敌方、含路人），只受「海克斯乱斗对局」双条件约束（队列白名单 + 该行至少一个 `playerAugment1-6` 非零）。

## Considered Options

- **仅车队成员的行（成员卡口径）**：针对性最强（"我方英雄该带什么"），但车队 5 人切到具体英雄×强化组合后每格只剩几局，小样本降透明度规则会整页生效，页面失去可用性。
- **仅车队对局里成员的行（七榜口径）**：最"正统"但要先过 `min-shared-members` 闸门，样本最薄，且带来"这局是车队局"与"这行是路人"的口径纠缠。
- **全库全量参与者行（选定）**：样本最厚；强化强度本不分敌我（敌方孙悟空带某强化的胜率同样回答"该强化强不强"）；项目已有先例——敌方窗口胜率同样消费路人数据，库内数据没有"只算自己人"的洁癖。

## Consequences

- 统计数字的语义是"**全库观测**的该英雄该强化表现"，不是车队视角；页头口径行必须写明"全库参与者行"，防止读者按车队口径误读。
- 出场率分母 = 该英雄在全库海克斯乱斗对局中的参与者行数；胜率分母 = 其中持有该强化的行数（两分母刻意不同，词条见 CONTEXT「强化胜率」）。
- 覆盖率计数（纳入局数/队列命中但无强化的局数）同样按全库口径统计，页头展示；排除计数用独立的轻量分组查询补齐，不随主扫描全量加载。
- 聚合为请求时内存实时计算（与七榜/周报/赛季报告同哲学，无物化表、无定时任务）；未来若数据量增长到实时聚合不可接受，可加 V13 物化表 + 一次性回补翻盘，方向不对称风险已评估。
- 数据库若存在异常版本行（如 25.xx 脏数据），会以"版本"维度直接出现在版本筛选器里污染默认视图——清理脏数据是本功能的前置运维动作（先核实画像、备份后删除）。
