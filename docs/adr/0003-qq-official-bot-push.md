# 0003-qq-official-bot-push.md

# 车队群推送通道采用 QQ 官方开放平台机器人（HTTP OpenAPI + WS 事件），而非第三方机器人框架

## Status

accepted

## Context

需求：开黑对局（车队对局）结束后，服务端自动把战报图与局后锐评推送到车队群（见 `docs/spec/post-game-broadcast.md`）。探索结论：

- 仓库内没有任何 QQ 集成先例（无 go-cqhttp / OneBot / webhook 任何依赖）；
- 服务端已有成熟的出站基建（Apache HttpClient 5 连接池 + 专用线程池 + 环境变量配置模式），新增出站调用成本低；
- 社区框架（go-cqhttp 等）已公开停止维护："由于 QQ 官方针对协议库的围追堵截……建议迁移至无头 NTQQ 项目"（go-cqhttp README / issue #2471），NTQQ hook 路线属非官方灰色地带，封号风险自担；
- 2026 年 QQ 官方开放平台现行文档（bot.q.qq.com/wiki）已统一"QQ 机器人"产品形态，可运行于普通 QQ 群，**个人实名认证**后即可被任意群添加（进群上限 500），群消息 HTTP API 支持**无需用户先 @ 的主动推送**（Bot 维度 60 条/分钟、单群 1000 条/天，对本功能"一局一两条"的用量充裕）。

## Decision

1. **通道 = QQ 官方开放平台机器人**（`q.qq.com` 创建 + 个人认证），走 OpenAPI：
   - 发送群消息：`POST /v2/groups/{group_openid}/messages`，鉴权用 `appId + clientSecret` 换 `access_token`（≤7200s），服务端新增出站客户端（复用 HttpClient 单例），不做"申请主动消息权限"（官方无此门槛，主动推送属文档支持能力）；
   - 服务端需**常驻一个 WebSocket 事件客户端**：接收 `GROUP_ADD_ROBOT` 入群事件以获取/核验目标群 `group_openid`，并保持机器人在线状态；事件通道与业务解耦，断线重连不影响发送队列；
   - 运营约束：机器人昵称/头像/简介过发布审核；内容遵守运营规范（避免骚扰式文案与高频轰炸）。目标群侧"允许接收主动消息"（`allow_proactive_msg`）若被关闭，发送将失败——上线时用自建群实测一条验证。
2. **消息形态 = "战报图 + 局后锐评文本"两条消息**：官方群消息一条只能一种 `msg_type`（纯文本 0 / Markdown 2 / 富媒体 7 互斥），图片与文字无法并列于一条，故拆两条：先发战报图（数据不依赖 AI，秒发），AI 锐评生成后补发文本（Q4/Q5/Q9 决策）。图片走富媒体通道：服务端本地渲染 PNG → `POST /v2/groups/{group_openid}/files`（分片上传，支持本地文件，`file_info` ttl 300s 现传现用）→ `msg_type=7` 发送。
3. **群绑定 = 单车队单群，配置声明**：`push.group-open-id` 与机器人凭证走 `application.yml` + 环境变量（复用 `team.roster` 单组现状），不建绑定表；多车队多群留待需求出现后再抽表（Flyway 约定不变）。
4. **失败语义**：所有发送与 AI 调用失败均落库（`match.push_status`），不静默；AI 全挂时发"缺席提示"文本，保证群里永远有交代。

## Considered Options

- **OneBot v11 网关（NapCat/Lagrange/go-cqhttp）+ HTTP 发送** → 否决：go-cqhttp 已停更（协议库被封），NTQQ 系 hook 方案属非官方灰色地带，账号封禁风险自担；多一个需自行维护的 bot 进程与协议层
- **QQ 官方开放平台机器人** → 采纳：正规路径、文档完善、个人可认证；代价是个人实名认证 + 发布审核 + 群侧主动消息开关不受控 + 机器人进群需群主/管理员操作
- **通用 Webhook（转发桥自建）** → 否决：等于把 OneBot 方案的自维护成本转嫁给用户自建桥，且无官方能力背书
- **只读不做（战报停留在 Web 端，人工转发）** → 否决：与"打完自动播报"的产品意图不符（周报分享图"发群用"是手动转发，正是本功能要消除的断点）

## Consequences

- 需要一次性的外部前置：开发者注册开放平台 + **个人实名认证** + 创建机器人过资料审核 + 目标群主把机器人拉进车队群 + 从入群事件取得 `group_openid` 填入配置（开发期可用"内部体验号码"或自建群测试）
- 机器人能力依赖官方平台政策：主动推送规则、频控、接口域名（2026-08 起统一 `api.bot.qq.com`）以官方文档为准，政策收紧时推送适配层（`qq-bot` 客户端）是唯一需要改动的边界
- 群/用户可在 QQ 客户端关闭"接收主动消息"，此时发送失败并落库 `FAILED`，由既有补推/状态机制呈现，不另做绕过
- 服务端新增两类常驻能力：WS 事件客户端 + 图片渲染线程池（Java2D headless，需随镜像打包中文字体，见 spec）
- 术语：车队群、局后播报、战报图、局后锐评 见 `CONTEXT.md`
